Closes #1

Summary
- Реализована предварительная валидация календаря через реестр провайдеров с локальным мок-режимом по умолчанию.
- Добавлены тесты для локального мок-режима, неверного CALENDAR_API_KEY и неизвестного CALENDAR_PROVIDER.
- Введена простая защита логов: ключ API и raw-ответы провайдера не попадают в логи или пользовательские сообщения.

Test Plan
- Локальный мок-режим: без CALENDAR_PROVIDER POST /bookings успешно создаёт бронь (валидные данные).
- Неверный CALENDAR_API_KEY: POST /bookings возвращает 403 с сообщением об ошибке API-ключа.
- Неизвестный CALENDAR_PROVIDER: POST /bookings возвращает 500 с информативным сообщением о незарегистрированном провайдере.
- Логи: при попытках загрузки провайдера в логах не появляется сам API-ключ; логи содержат только идентификатор провайдера.

Notes
- PR включает минимальную инфраструктуру реестра провайдеров и пример заглушек провайдеров (google-calendar).
- В дальнейшем планируется полноценно внедрить реестр и реальные реализации провайдеров (Google Calendar, Outlook и т.д.).
